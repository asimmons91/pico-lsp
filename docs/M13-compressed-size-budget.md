# M13 — Compressed-size Budget

**Status:** Planned  
**Depends on:** M12  
**Release target:** v1.2.0 (batched with M11, M12, M14)  
**Roadmap:** [ROADMAP.md](ROADMAP.md)

## Outcome

Cart budget reporting covers PICO-8's compressed code-size limit in addition to
tokens and characters. `pico8/cartInfo`, the budget code lens, and diagnostics
show the compressed size of the assembled `__lua__` code and warn before the
documented limit.

**Demo:** A cart near the compressed-size limit shows the compressed byte count
in the budget code lens and `pico8/cartInfo`. Crossing the warning threshold
publishes a warning; exceeding the limit publishes an error. The value matches a
PICO-8-compatible compressor for the same source.

## Scope

### In scope

- A PICO-8-compatible code compressor in Go, used only for size estimation.
- Compressed-size reporting for the assembled cart, with per-file contributions
  where meaningful.
- Compressed-size fields in `pico8/cartInfo` and the cart-budget code lens.
- Warning/error diagnostics with the documented compressed-size limit.
- Configuration and documentation for the new budget.
- Fixture validation against PICO-8/reference compressor output.

### Out of scope

- Writing or exporting `.p8.png` carts.
- Executing cart code or invoking PICO-8.
- Changing token/character counting semantics.
- Compressed-size budgets for unassembled standalone `.lua` files unless they
  belong to a cart.
- API version selection and editor clients.

## Requirements

- Implement or integrate a PICO-8-compatible compressor. Prefer a proven
  MIT-compatible reference implementation and keep it isolated behind a small
  internal package (for example `internal/p8compress`) so it can be replaced.
- Use the assembled cart code after include flattening and tab joining. The
  compressed size describes the code that PICO-8 would store, not the source
  file size.
- Compressed-size limit: 15616 bytes, warning from 90% of the limit (14054
  bytes), error when exceeded. The exact values must be cross-checked against
  the PICO-8 manual/reference implementation during implementation.
- New diagnostic code `compressed-size-limit`:
  - Warning at or above the warning threshold.
  - Error when the limit is exceeded.
  - Documented in [diagnostics.md](diagnostics.md) and suppressible where the
    existing diagnostic policy allows.
- `pico8/cartInfo` adds compressed size, limit, threshold, and a status field
  without breaking existing fields.
- The budget code lens shows compressed size alongside token/character
  budgets. Keep the code lens compact and accessible.
- `pico8.limits.codeLens` and `pico8.limits.diagnostics` continue to control
  whether compressed-size UI/diagnostics are shown.
- Compressor failures or unsupported inputs degrade to an unavailable value,
  not a crash or a false limit error.
- Performance: compression on a 64 KB cart must remain within the full-analysis
  budget and must be memoized per cart snapshot.
- Do not include compressed size in the token/char diagnostics; use the new code
  and clear messages.

## Testing

- Compressor unit tests and table-driven parity fixtures generated by PICO-8 or
  a validated reference implementation.
- Fixtures for uncompressed, simple, repetitive, high-entropy, UTF-8, shorthand,
  and near-limit cart code.
- `pico8/cartInfo` tests for fields and thresholds.
- LSP code-lens and diagnostic e2e tests at below-warning, warning, and error
  sizes.
- Corpus validation: no compressed-size errors on valid corpus carts, and
  informational values remain stable.
- Performance test for a 64 KB assembled cart.
- Documentation updates for configuration, diagnostics, and cart budgets.

## Exit criteria

- [ ] Assembled cart compressed size is reported consistently.
- [ ] `pico8/cartInfo` and the code lens expose compressed size and status.
- [ ] Warning/error thresholds match the documented limit and are tested.
- [ ] Compressor output matches PICO-8/reference output on fixtures.
- [ ] Failures degrade gracefully and performance stays within budget.
- [ ] Documentation and diagnostic references are updated.
- [ ] Existing token/character behavior and tests do not regress.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Compressor output differs from PICO-8 | Fixture parity tests; keep the value informational until parity is proven. |
| Compressor is slow on large carts | Memoize per snapshot, benchmark the 64 KB cart, and keep the implementation dependency-free. |
| New limit noise on valid carts | Corpus thresholds, warning at 90%, error only when exceeded, and configurable disable paths. |
| `.p8.png` export expectations | Explicitly document compressed-size reporting as read-only; export remains out of scope. |
| Limit values change across PICO-8 versions | Centralize the 0.2.7 constants and add API-version selection in the backlog milestone. |
